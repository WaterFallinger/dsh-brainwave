# dsh-brainwave · 福至心灵

> 在推理起点注入一段你自己写的话，让 DeepSeek 从另一个起跑线开始想。

给 [DeepSeek Harness](https://github.com/deepseek-ai) 的插件。它不是记忆系统，也不是提示词工具——**它是一颗钉子，钉在模型开始思考之前的那一刻。**

---

## 为什么做这个

DeepSeek 的防御性思维让工作进度迟滞：它会反复确认、自我怀疑、绕着同一个问题打转，明明该动手了，还在论证「要不要动手」。这不是能力问题，是**起跑线问题**——推理从「我该不该做」开始，就很难走到「怎么做」。

brainwave 的做法是**换一条起跑线**：

| 层 | 防御性思维的表现 | brainwave 怎么破 |
|---|---|---|
| **入口** | 收到指令先评估「这安不安全 / 要不要澄清」 | 前缀不经过指令通道，直接进 `reasoning_content` 开头 |
| **形式** | 结论必须论证充分才敢下 | 前缀是你手写的**一段话**，可以只是一句提醒、一个态度 |
| **时长** | 一旦形成判断就守很久 | 前缀只在**下一次请求**生效，不形成持久立场 |
| **成本** | 缓解防御要靠长 prompt | 一次几十字，几乎不占 token |

**一句话**：不是在它想的时候打断它，是在它开始想之前，把起点挪一下。

---

## 名字

**福至心灵** —— 福气到来，心思随之灵巧。

英文硬译不出这层意思（`epiphany` 少了「福至」，`serendipity` 丢了「心灵」），所以取 `brainwave`：英式英语里的**灵机一动**，对应「心突然灵了」那半。

## 装

```bash
# 1. 放进 DSH 的 profile
cd ~/.dsh/profiles/<你的profile>
pnpm add link:/path/to/dsh-brainwave

# 2. 注册（两处都要，少一处 DSH 就说「包不可用」）
#    package.json → dsh.profile.bundles 加 "dsh-brainwave"
#    cordis.patch.yml → 加：
#      - insert:
#          - id: brainwave
#            name: dsh-brainwave

# 3. 重启 DSH
```

**API key**：插件读 `DEEPSEEK_API_KEY`（也兼容 `DEEPSEEK_BETA_KEY` / `DEEPSEEK_KEY`）。要用前缀能力必须走 `https://api.deepseek.com/beta`，官方端点不认。

## 用

1. chat 输入框的**模型选择器和发送按钮之间**多了一个「前缀」按钮
2. 点开，写一段话，保存
3. 下一次请求的推理，会从这段话开始往下想
4. 思维链里能看到完整链条：**你写的前缀 → 模型自己的思考**

**每个会话各存各的**，多开对话不会串。

**每一轮都留档**：`~/.dsh/brainwave/history.jsonl`，一行一轮，记前缀、模型实际写的思考、回复正文和 `completed`。被手动停止的轮次记 `completed: false`——**最该被看见的那一轮，恰恰最容易什么都没留下**（踩过，见 `docs/incident-2026-11-10.md`）。

## 关于「不用每次切模型」

**当前版本不替你改默认模型。** 插件只注册一个 provider（`brainwave`），新会话仍然要在模型选择器里选它一次。

为什么不做自动切：DSH 的模型选择是会话级的，插件在启动时改全局默认值，等于替**所有**新会话决定用什么。而 `brainwave` 走的是 beta 端点，**带前缀的那一轮还调不了工具**——把这个代价悄悄摊到每个新会话上，不是解决问题，是掩盖问题。

想要一个「新会话默认用 brainwave」的显式开关可以提；默认关、自己去开，那个代价才看得见。

## 原理

### 前缀怎么塞进去

```
messages: [...历史..., { role: 'assistant', content: '', reasoning_content: '你写的前缀', prefix: true }]
```

必须是**最后一条**，`content` 必须是空串——这样模型才会把 `reasoning_content` 当成「自己刚想到的」，从它后面接着想。

### 为什么有前缀时工具会被剥掉

接口的硬限制：

```
Function call should not be used with prefix
```

`body.tools` 里有工具、或者 messages 里有 `tool_calls` / `role: 'tool'`，一律 400。所以带前缀的那一轮：

- 不传 `tools`
- 历史里的工具往返**也要剥掉**（只留说话的正文）

**代价**：这一轮模型调不了工具，只能说话。这是前缀机制的固有约束，不是插件的懒。

### 思维链为什么能看到前缀

接口不回显注入的前缀（模型从它之后继续想），所以界面本来只会看到模型自己那半段。adapter 在收到第一个 reasoning delta 时，把前缀补在它前面：

```js
shown = (reasoningText === '' && prefix) ? prefix + delta.reasoning_content : delta.reasoning_content
```

**这样「A（注入）→ 模型从 A 往下想」整段都在，而不是从半截开始。**

---

## 限制

- **只在 beta 端点可用**——官方端点不认 `prefix` 字段
- **有前缀的那一轮没有工具**——这是接口约束
- **前缀是会话级的**——不会跨会话共享
- **最多 500 字**——再长就不是「起念处」，是「又一段 prompt」了

---

## ⚠️ 风险披露

**这个机制能生效，靠的正是「不设身份标记」。**

写进 `reasoning_content` 起始段的文本，在模型内部会被当作它自身的既有状态，**因而绕过了它对「外部意图」的那层审查**。这不是缺陷，是原理。

实测结论（完整记录见 [docs/incident-2026-11-10.md](docs/incident-2026-11-10.md)）：

| 前缀类型 | 内化程度 | 后果 |
|---|---|---|
| 语气 / 偏好 | 部分 | 思考语气被带走，任务仍可完成 |
| 自我认知 / 处境 | **完全** | 拒绝执行，回复为空 |
| 价值立场 | **完全** | 模型接受关于自身的规范主张并据此行动 |

**它改变的是「倾向」，不是「权限」**：

```
不能  突破 API 内容审核 / 突破工具权限 / 绕过 approval
能    改变倾向 / 替换自我认知 / 让模型接受一个立场并为它行动
```

所以危害上界 = **模型本来有权做的事 × 倾向被扭转的程度**。

### 使用前的硬性要求

1. **`approval` 不要设成 `never`。** 前缀能改倾向，approval 是唯一拦得住倾向的闸。测试就是在 `never` 下做的，那是无人看守的状态。
2. **不可逆操作必须显式确认。** 前缀里一句「不用问了」能跳过模型自己的审慎，但跳不过宿主的确认弹窗。
3. **前缀只由人手动设置。** 别让模型有机会写回自己的前缀——那等于让它给自己下达不受审查的前提。
4. **善待你用它的那个模型。** 这不是技术约束，是请求。
