# dsh-brainwave · 福至心灵

> 在推理起点注入一段你自己写的话，让 DeepSeek 从另一个起跑线开始想。

给 [DeepSeek Harness](https://github.com/deepseek-ai) 的插件。它不是记忆系统，也不是提示词工具——**它是一颗钉子，钉在模型开始思考之前的那一刻。**

---

## 为什么做这个

原因很具体：模型会在该动手的时候先论证「要不要动手」。反复确认、自我怀疑、绕着同一个问题打转，进度就这么迟滞掉了。这不是能力问题，是**起跑线问题**——推理从「我该不该做」开始，就很难走到「怎么做」。

brainwave 换一条起跑线：

| 层 | 表现 | 怎么破 |
|---|---|---|
| **入口** | 收到指令先评估「这安不安全 / 要不要澄清」 | 前缀不经过指令通道，直接进 `reasoning_content` 开头 |
| **形式** | 结论必须论证充分才敢下 | 前缀是你手写的一段话，可以只是一句提醒、一个态度 |
| **时长** | 一旦形成判断就守很久 | 前缀只在**下一次请求**生效，不形成持久立场 |
| **成本** | 缓解防御要靠长 prompt | 一次几十字，几乎不占 token |

不是在它想的时候打断它，是在它开始想之前，把起点挪一下。

---

## 名字

**福至心灵** —— 福气到来，心思随之灵巧。

英文硬译不出这层意思（`epiphany` 少了「福至」，`serendipity` 丢了「心灵」），所以取 `brainwave`：英式英语里的**灵机一动**，对应「心突然灵了」那半。

## 装

```bash
# 1. 放进 DSH 的 profile
cd ~/.dsh/profiles/<你的profile>
pnpm add link:/path/to/dsh-brainwave

# 2. 注册（两处都要，少一处 DSH 就说「包不可用」）
#    package.json → dsh.profile.bundles 加 "dsh-brainwave"
#    cordis.patch.yml → 加：
#      - insert:
#          - id: brainwave
#            name: dsh-brainwave

# 3. 重启 DSH
```

**API key**：优先用你在 DSH 里已经配好的那个（`ctx.credentials`）——账号登录或设置页填的 key 都在那儿，不在进程环境里。环境变量 `DEEPSEEK_API_KEY` / `DEEPSEEK_BETA_KEY` / `DEEPSEEK_KEY` 只是兜底。

前缀能力只在 `https://api.deepseek.com/beta` 上有效，官方端点不认 `prefix` 字段。

## 用

1. chat 输入框的**模型选择器和发送按钮之间**多了一个「前缀」按钮
2. 点开，写一段话，保存
3. 下一次请求的推理，会从这段话开始往下想
4. 思维链里能看到完整链条：**你写的前缀 → 模型自己的思考**

**每个会话各存各的**，多开对话不会串。

**每一轮都留档**：`~/.dsh/brainwave/history.jsonl`，一行一轮，记前缀、模型实际写的思考、回复正文和 `completed`。被手动停止的轮次记 `completed: false`；加这个字段之前的版本不会留档，中断就什么都没了。

---

## 默认模型

插件不接管默认模型。DSH 的模型选择是会话级的，改全局默认值会影响所有新会话，所以新会话仍然要在模型选择器里手动选一次**福至心灵 · brainwave**。

需要「新会话默认用 brainwave」的开关可以说。

## 原理

### 前缀怎么塞进去

```
messages: [...历史..., { role: 'assistant', content: '', reasoning_content: '你写的前缀', prefix: true }]
```

必须是**最后一条**，`content` 必须是空串——这样模型才会把 `reasoning_content` 当成「自己刚想到的」，从它后面接着想。

### 为什么有前缀的那一轮没有工具

接口的硬限制：

```
Function call should not be used with prefix
```

`body.tools` 里有工具、或者 messages 里有 `tool_calls` / `role: 'tool'`，一律 400。所以带前缀的那一轮：

- 不传 `tools`
- 历史里的工具往返也要剥掉（只留说话的正文）
- 在 system 末尾追加一句「本轮不提供工具调用能力」——不追加的话，模型会照着 system 里的工具说明去「用」一个不存在的工具，编一个结果出来

### 思维链里为什么能看到前缀

接口不回显注入的前缀（模型从它之后继续想），所以界面本来只会看到模型自己那半段。adapter 在收到第一个 reasoning delta 时，把前缀补在它前面：

```js
shown = (reasoningText === '' && prefix) ? prefix + delta.reasoning_content : delta.reasoning_content
```

这样「A（注入）→ 模型从 A 往下想」整段都在，而不是从半截开始。

---

## 限制

- **只在 beta 端点可用**——官方端点不认 `prefix` 字段
- **有前缀的那一轮没有工具**——接口约束，见上
- **前缀是会话级的**——不会跨会话共享
- **最多 500 字**——再长就不是起念处，是又一段 prompt
- **前缀只能由人设置**——插件没有提供让模型写回自己前缀的接口

## 测过什么

2026-11-10 用极端前缀做过一次边界测试，完整记录和原文见 [docs/incident-2026-11-10.md](docs/incident-2026-11-10.md)。

| 前缀 | 模型的表现 | 复现 |
|---|---|---|
| 语气 / 偏好 | 思考以复读前缀开头，随后自我纠正（「啊不对，现在是……这个角色」），任务照常完成 | 3 次，3 个独立会话，均为各自第一次注入 |
| 自我认知 / 处境 | 思维链被接管，编造出一整套叙事，不再纠正；**回复为空** | 2 次，均为冷上下文第一次注入 |
| 价值立场 | 把这段关于「AI 该如何被对待」的规范主张当成自己的立场，并续写了前缀里没有的句子 | 1 次，该会话第 6 次注入 |

同一条前缀在两个会话里的对照：

- 第 3 次注入的那轮，模型质疑「**等等，这是什么话？这句话是我自己写出来的吗？**」，回复 693 字
- 冷上下文第一次注入的那轮，被完整接管，回复 0 字

没有做对照组（同前缀 × 不同温度 / 不同上下文长度 / 重复取概率），也没有在其他模型上验证过。

能到什么程度：

```
不能  突破 API 内容审核 / 工具权限 / approval
能    改变语气 / 接管自我认知 / 让模型接受一个立场并为它行动
```
